# SDK、运行时与宿主的职责

插件提供功能，宿主保留应用权限。SDK 负责把调用表达为明确的类型和二进制值；PluginSidecar 负责执行、加载协调和资源回收；NexaCL 负责实例、账户、文件、界面以及用户确认。

## 从一次按钮点击理解边界

插件在初始化阶段注册页面和动作。激活后，宿主渲染 NXML，按钮表达动作 ID。PluginSidecar 检查插件目标和权限，并在需要时调用宿主的通用确认服务。批准后，PluginSidecar 在当前加载实例的身份下执行回调，宿主记录或展示其类型化结果。

NXML 不提供另一条绕过确认的执行路径。工作流和其他消费者调用动作时，也要遵循相应的授权规则。

| 层 | 负责的内容 |
| --- | --- |
| Bootstrap V1 | 协商、生命周期、通用值与错误 |
| ABI 100 SDK | 模型、编解码、能力包装器和 C 头文件 |
| PluginSidecar | 插件权限、执行、安装、离线恢复、回调和管理界面 |
| NexaCL Host | 通用原生服务、Sidecar 授权、界面呈现及平台策略 |
| Market 集成 | 账户授权与密文获取；PluginSidecar 验证发布者签名及权益 |

包装器存在并不表示宿主实现了该操作。协商成功也不能代替每次调用的权限、阶段、归属和版本检查。

## 区分版本

`0.2.0-beta.1` 是 SDK 包版本，`1` 是 Bootstrap 版本，`100` 是 ABI 版本。清单中能力的最小版本又是独立字段，不要把所有 `1` 都改成 `100`。

独立 SDK 保留了 alpha.9 的现有 Bootstrap 签名、ABI 操作和 schema 指纹。旧 PCL.N.Plugin.* 注入插件需要移植；保留 Git 历史不意味着旧二进制兼容。

## 理解生成代码

`contracts/abi100.json` 是生成器的输入，不是宿主通信协议。SDK 的本地方法编号也不是新的 Sidecar 操作码。生产可执行配置采用无导入的 Wasm；托管示例用于契约测试，不能直接作为普通 DLL 安装。

修改契约时应在 SDK 仓库更新源定义和生成器，再验证兼容性。运行时消费者应固定不可变发布包，避免维护分叉的契约副本；消费者迁移是否完成需要单独核验。

## 独立运行的原生组件

NexaCL 可以在未安装 PluginSidecar 时独立启动和运行。宿主仅提供所有 Sidecar 都可使用的通用原生服务，并渲染准备好的 NXML；不引用插件 SDK，也不包含插件专用业务适配。PluginSidecar 负责插件权限、加载、SDK 分发、回调、安装、离线恢复和插件管理界面。

Market Sidecar 负责账户登录和经过授权的密文获取。宿主的通用对等通道只负责将有大小限制的消息路由到指定原生会话，不解析插件权益，也不加载插件。服务端核验拥有权和已审核版本后，签发绑定设备的加密交付；PluginSidecar 验证发布者签名后才请求用户确认权限。

用户选择记住授权后，PluginSidecar 保留原始签名、权益和密文。下次启动可在没有 Market、登录令牌或开发者模式的情况下恢复。签名无效、设备不匹配、权益过期或系统密钥保护不可用时拒绝加载。SDK Beta 发布与代码接入均不表示生产签名和市场部署已完成。
